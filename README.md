# imx-sectool

On NXP i.MX processors, fuses and secure boot are usually handled from the
U-Boot console with the `fuse` and `hab_status` commands. imx-sectool brings
the same commands to Linux, so you can check and provision a device over SSH
or from a script, without a serial console.

It also shows information that Linux does not give today: the Boot ROM log,
how the board booted, the JTAG / secure debug mode, and a security checklist.

HAB commands need no device-tree change or extra kernel module. Fuses use
nvmem; Boot ROM data uses fixed, read-only `/dev/mem` regions. On i.MX8QM and i.MX8QXP,
AHAB events need an [optional mailbox overlay and stock UIO driver](docs/ahab-uio.md).
Without that setup, `ahab_status` still reports available lifecycle information.

> **Warning:** fuses are one-time programmable. A wrong `fuse prog` can break
> a device for good. Use at your own risk.

## Usage

All commands need root.

```
imx-sectool fuse read 1 3          # same as U-Boot 'fuse read'
imx-sectool fuse read JTAG_SMODE   # fuse fields also work by name
imx-sectool hab_status             # same output as U-Boot 'hab_status'
imx-sectool ahab_status            # SECO lifecycle; events with optional UIO setup
imx-sectool romlog                 # Boot ROM event log
imx-sectool bootinfo               # boot mode, primary or secondary image
imx-sectool fusemap                # security fuses with their meaning
imx-sectool debug-status           # JTAG / secure debug mode
imx-sectool audit                  # secure boot and secure debug checklist
```

If the binary is called `fuse` or `hab_status` (for example through a
symbolic link), it works like the U-Boot command, with the same output and
exit codes.

Add `--json` to get machine-readable output. `debug-status` and `audit` can
also check the fuses against the `imx-config.fuse` file generated by
[meta-toradex-security](https://github.com/toradex/meta-toradex-security)
with `--profile <file>`.

## Build

The tool is plain C11 and needs only libc.

```
make                                            # native build
make CC=aarch64-linux-gnu-gcc LDFLAGS=-static   # static build for arm64
make CC=arm-linux-gnueabihf-gcc LDFLAGS=-static # static build for i.MX7
make check                                      # host tests (needs python3)
make install PREFIX=/usr INSTALL_ALIASES=1      # also installs 'fuse' and 'hab_status'
```

## Supported SoCs

| SoC | Status |
|---|---|
| i.MX8M Plus | All commands except `ahab_status`, tested on hardware |
| i.MX8M Mini | Fuse commands, `fusemap`, `debug-status` and `audit`, tested on an open board. `hab_status`, `romlog` and `bootinfo` report "unavailable" until the Boot ROM memory regions are checked on hardware |
| i.MX7Dual | Fuses, HAB events and debug checks tested on an open board. `bootinfo` reads the boot device through the ROM pointer and shows the primary/secondary selection. The ROM log reports the image selection, authentication result and entry address, but not the eMMC boot partition; U-Boot usually clears the reset cause |
| i.MX8QM | `ahab_status`: lifecycle and firmware version; events through optional UIO setup, tested on hardware |
| i.MX8QXP | `ahab_status`: lifecycle and firmware version; events through optional UIO setup, tested on hardware |

On any other SoC the tool stops before reading anything.

Planned:

| SoC | Secure boot | Notes |
|---|---|---|
| i.MX8M Nano, Quad | HABv4 | Same family as the i.MX8M Plus; next to come |
| i.MX93, i.MX91, i.MX95 | AHAB (EdgeLock Enclave) | Adds `ahab_status` |
| i.MX8ULP | AHAB (EdgeLock Enclave) | |
| i.MX6, i.MX6UL/ULL, i.MX7Solo | HABv4 | HAB event area to be found on hardware |
| i.MX8DXL | AHAB (SCU) | Driver and mailbox support to be checked |

See [DESIGN.md](DESIGN.md) for the details.
The [i.MX7 secondary-boot note](docs/imx7-secondary-boot.md) explains
same-partition fallback and a proposed bootloader rollback mechanism.
